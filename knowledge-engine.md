# Knowledge Engine — Milestone 4

## Implemented
- Five built-in synthetic Nova City reference notes.
- Hybrid lexical retrieval using BM25-style term scoring and TF-IDF cosine similarity.
- Bounded text chunking for user-added documents, preserving a parent document ID for citations.
- Plain-text/Markdown note ingestion through `POST /knowledge/ingest`.
- Local JSON persistence with atomic file replacement.
- Document listing and deletion endpoints.
- Input limits, reserved ID protection, duplicate detection and a bounded local document count.
- Retrieval evaluation script with Hit Rate@1, Hit Rate@3 and Mean Reciprocal Rank.

## API examples

`POST /knowledge/ingest`

```json
{
  "id": "USER-MOBILITY-01",
  "title": "Community mobility note",
  "domain": "mobility",
  "text": "Residents use buses and bicycles for short journeys."
}
```

`GET /knowledge/documents` lists user-added notes. `DELETE /knowledge/documents/USER-MOBILITY-01` removes one note. Built-in `NOVA-*` documents cannot be overwritten or deleted through this interface.

## Current retrieval limits
- BM25 + TF-IDF are lexical methods. TF-IDF is not a neural embedding model.
- Answers are extractive, not generated by an LLM.
- The local JSON store is suitable for a single-user prototype, not concurrent production use.
- Uploaded files, PDF parsing, database-backed storage, semantic embeddings and reranking are not included yet.
- Ingested notes are user-provided and are not independently verified for factual accuracy.

## Evaluation
Run from `backend/`:

```bash
python evaluate_retrieval.py
```

The evaluation set is small and synthetic. It checks regression behavior, not real-world retrieval quality.
